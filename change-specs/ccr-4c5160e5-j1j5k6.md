# 0093: Paired-rule lesson format

Priority: critical for adoption. Lessons are the layer a new user feels first.
They get injected into every matching prompt, and today what gets injected is
expensive, truncated, and hard to act on.

## Context and problem statement

`memory/lessons/<topic>.md` entries are distilled by
`agents/np-flow-episodic-maintain.md` §5b into a **Symptom / Why / Do / Avoid**
body (failures) or a **Title / When / Do** body (successes). `lesson_recall.py`
injects them on a session's first prompts.

Four forces pull against that shape:

1. **Cost.** The Symptom field is scenario narrative. It is injected on every
   matching prompt, but the session needs only the rule.
2. **Silent truncation.** `lesson_recall._lesson_blocks` keeps only lines that
   start with a bold `**Header:**`. A wrapped field loses its continuation lines,
   so a Symptom or Why arrives cut mid-sentence. The distiller never learns this.
3. **Unpaired rules.** "Avoid X" with no "do Y instead" makes the session
   improvise. Nothing ties an Avoid to its Do.
4. **No lintable contract.** Scope (*when*) and reason (*why*) are optional prose,
   so nothing can check that a rule says where it applies or why. Without those,
   a rule gets applied everywhere and can't be weighed against a conflicting one.

## Considered options

1. **Keep the current shape, fix the truncation only.** Good: smallest change.
   Bad: keeps the narrative cost and the unpaired, unlintable rules.
2. **Bare DO / DON'T bullets.** Good: cheapest to inject. Bad: drops scope and
   reason, so rules are applied too broadly, and there's no basis for exceptions.
3. **Paired rule with labelled when + why, narrative kept in episodic.** Good:
   cheap to inject, lintable, pairs avoid-with-alternative, and the evidence
   survives one backlink away. Bad: needs a migration and a recall parser change.

## Decision

We will make each lesson entry one paired-rule line, grouped under an
objective heading inside the existing `memory/lessons/<topic>.md`:

```markdown
## <objective>
- DON'T <x> → DO <y> — **when** <scope> — **why** <reason>. [[episodic/<topic>]]
```

- **Pairing:** DON'T → DO is the default. A lone DO is allowed (a win with no
  real anti-pattern; we don't invent a DON'T). A lone DON'T is a lint finding.
- **when** and **why** are required, labelled, and separate. *When* decides
  whether the rule fires. *Why* lets a session handle a case the *when* didn't
  anticipate.
- **Budget:** at most two rendered lines (about 320 characters) per entry.
- **Evidence:** the narrative stays in `memory/episodic/`, linked by
  `[[episodic/<topic>]]`. It is not copied into the lesson.
- **Unchanged:** the frontmatter (`provenance`, `topic_triggers`, `seen`,
  `enforce`), the `INDEX.md` table, `lesson_guard.py`, and the directory layout.
  It stays shallow: no new subfolders.

Work items:

1. Add `engine/setup/np_lesson_format.py` (stdlib-only): `parse(text)` and
   `lint(text)`, where `lint` returns findings with codes `missing-when`,
   `missing-why`, `lone-dont`, `too-long` and `legacy-format`.
2. Make `lesson_recall.py` inject paired-rule lines and the objective heading
   (never an empty `[topic]` tag), still reading legacy bodies during migration.
3. Rewrite §5b of `np-flow-episodic-maintain.md` so the distiller emits the
   paired format and runs `lint` before its commit, reverting the lessons write
   on any finding.
4. Extend `np-migrate-lessons.py` to convert legacy bodies (Do/Avoid → pair,
   Symptom → episodic backlink). The migration must be idempotent and keep
   `enforce` byte-for-byte.
5. Discoverability: the maintain pass adds a `Lessons: [[lessons/<topic>]]`
   backlink to the matching skill or wiki topic page, so hosts without the
   recall hook still find lessons.

Chosen option: "Paired rule with labelled when + why", because it is the only
option that cuts injection cost and also gives the distiller a contract it can
be checked against.

## Non-goals

- Changing skill bodies. Procedures don't break down into DO/DON'T pairs.
  Only "Gotchas" sections may adopt the shape later, under a separate spec.
- A deeper directory hierarchy. Recall matches on `topic_triggers`, not paths.
- Changing `enforce` semantics or `lesson_guard.py`.

## Cross-cutting concerns

- Security: no new input surface. `enforce` blocks pass through the migration
  unchanged and are asserted byte-for-byte.
- Privacy: shorter injected text passes through the same `pii_filter`. The
  migration moves narrative into episodic, which is already PII-filtered on
  recall.
- Observability: lint findings go into the maintain report, and the
  `lesson-recall` signal is unchanged.

## Consequences

- Good, because the per-prompt injection shrinks by at least half for the same
  knowledge (asserted below).
- Good, because the truncation defect goes away: each rule is a single line.
- Good, because the distiller's output becomes machine-checkable.
- Bad, because there is a one-time migration of existing overlay lessons.
- Neutral, because recall reads both formats until the migration has run on
  every machine.

## Rollback

1. Toggle it off right away: `cli.py toggle lessons off`. Recall stops injecting
   on every machine after the next sync, and `lesson_guard` stays governed by
   its own state.
2. Revert the `lesson_recall.py` and `np-flow-episodic-maintain.md` commits. The
   dual-format reader means un-migrated legacy files keep working.
3. Restore migrated overlay lessons from the overlay's git history
   (`git -C "$NP_CONTENT_DIR" checkout <pre-migration-sha> -- memory/lessons`).
   The migration commits separately, so this is one revert.
4. Re-enable `lessons`.

## Deviations

- **Paired injection drops the preamble, topic tag and backlink.** The ≤ ½
  legacy-size assertion leaves room for only the objective line plus the rule
  itself, so `lesson_recall.py` injects a paired entry as `<objective>:` and the
  rule with its `[[episodic/…]]` link stripped (success objectives carry a
  ` (worked before)` suffix in place of the success preamble). Legacy entries
  keep their preamble and `[topic]` tag, and a body-less entry injects nothing.
- **Legacy recall truncation is left as is.** `TestBaseline` pins the
  first-line-only reading of legacy fields, so the fix for wrapped fields is
  the migration (which joins them) rather than a recall change.
- **Body conversion is a separate `--bodies` mode** of `np-migrate-lessons.py`.
  The default mode (playbooks/strategies → lessons) keeps its byte-for-byte body
  contract, which `test_migrate_lessons.py` asserts. The converted narrative is
  kept verbatim in `memory/episodic/<topic>.md`.
- **`lesson_recall.py` loads `engine/setup/np_lesson_format.py` by path**
  (importlib, fail-open to the legacy-only reader), so the parser has one home
  inside the blast radius.
